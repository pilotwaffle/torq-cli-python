## Findings

1. **High: P2 lacks a real file-editing execution path.** The plan proposes existing governed services as the implementation mechanism. `adapters/live_provider.py:266` forbids tools and filesystem access and line 298 disables tools. `domain/stage_response.py` only accepts a short builder proposal string. `docs/design/governed-change-transaction.md` explicitly remains design-only and documents approval without applying a change. Starting an existing live run cannot satisfy the proposed P2 exit gate. Add explicit dependencies for project isolation, editable workspace, actual command/check execution, pinned change artifacts, and governed application/acceptance semantics before claiming build parity.
2. **High: trust explanation conflates dry-run mode with invalid evidence.** `application/demo.py:execute_demo` uses the same `RunController.start` that creates the certificate and verifies receipts. An isolated no-provider experiment in this review returned dry_run / verified / certificate_exists=True. The prior statement that demo runs cannot be verified is incorrect. The launcher passes a collection parent to a single-run projector, which is an independent concrete defect. Session mutability and tool capability remain separate checks.
3. **Medium: queued follow-ups are promised without an implementation contract.** The working screen says the message sends when a step finishes. Define a durable queue with revision/cancellation/recovery semantics or keep text as an explicitly unsent draft requiring manual Send. The first increment adopts manual Send.
4. **Medium: continuation and notification baselines are inaccurate.** `chat_runtime.py:_provider_prompt` replays signed history despite the child provider's disabled persistence. `fleet.js:notifyActions` already provides notifications for open actions. Distinguish build continuation from conversation history and new completion alerts from existing action notifications.
5. **Medium: draft persistence statements conflict.** The plan says drafts never get lost and shows saved-local text while permitting memory-only drafting. Display persistence status from actual successful storage. Scope by an opaque root/run identity, preserve edits during submit, and document retention.

## Disposition

`2026-09-16-dashboard-g1d-build-contract.md` defines a bounded P0/P1 implementation for independent Sol G1R review. It preserves existing trust and mutation semantics, adds the friendly workspace, and reports the missing execution capability honestly. Full P2/P3 remain explicit follow-on requirements; this UI increment must not be labelled their completion.
